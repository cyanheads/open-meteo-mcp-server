# 0.6.1 — 2026-11-17

## Added

- **`openmeteo_get_marine` takes `models` and `forecast_days` up to 16** ([#104](https://github.com/cyanheads/open-meteo-mcp-server/issues/104)): `models` names any of ten marine models (`best_match`, `ecmwf_wam`, `ncep_gfswave025`, …); with 2+ every hourly and daily column is suffixed, and `current_variables` beside 2+ models fails as `current_multi_model`. The coverage-gap recovery and all-null notice are worded per call and say a point on land or under sea ice has no wave data from any model.

## Changed

- **`openmeteo_search_locations` `count` takes up to 100** ([#102](https://github.com/cyanheads/open-meteo-mcp-server/issues/102)), default 5. A larger value is lowered to 100 with a `notice`; `OPENMETEO_CLAMP_LIMITS=false` advertises 100 as the maximum and rejects a larger value.
- **`openmeteo_get_climate` with `models` omitted or blank sends and echoes `MRI_AGCM3_2_S`** ([#103](https://github.com/cyanheads/open-meteo-mcp-server/issues/103)): output `models` is always present, and `content[]` prints it in place of `API default`.
- **`current_multi_model` counts distinct models and names them**, in one wording shared by `openmeteo_get_forecast` and `openmeteo_get_marine`.
- **`openmeteo_dataframe_query` `sql` description** covers the member-count pattern on a multi-model ensemble table, whose columns end in the model name.
- **Server `instructions`** state the new marine, ensemble, and climate behavior, and that Open-Meteo names only the first unknown model in a rejected list.
- **`open-meteo-guide` skill 1.0.1 → 1.0.2:** ensemble member counts across several models.
- **Tests:** the `stays linear on %s` timing tests set a per-test timeout of `0`; a marine test regex is anchored on word boundaries.

## Fixed

- **A comma inside a name element is split into separate names** ([#98](https://github.com/cyanheads/open-meteo-mcp-server/issues/98)): `["temperature_2m,precipitation"]` meets the cadence, `current_multi_model`, and notice-attribution checks that two elements do, and `[","]` fails as `no_variables_requested`. One model named twice beside `current_variables` counts as one model and is answered.
- **`openmeteo_get_ensemble` answers several comma-separated `models`** ([#98](https://github.com/cyanheads/open-meteo-mcp-server/issues/98)): `model` lists them, `member_count` sums their members, and the `notice` gives each model's count and column naming; a model named twice counts once.
- **A 4xx that is not an Open-Meteo input rejection fails once as `upstream_rejected`** ([#99](https://github.com/cyanheads/open-meteo-mcp-server/issues/99)), `ServiceUnavailable` with `data.status` and `data.retryable: false`, declared on the nine tools that call the service. 0.6.0 reported an error page, JSON without the error envelope, or an empty body as an input error or retried it three times; HTTP 414 is unchanged.
- **`tilt` (0–90) and `azimuth` (−180–180) on `openmeteo_get_forecast`, `openmeteo_get_historical`, and `openmeteo_get_ensemble`** ([#101](https://github.com/cyanheads/open-meteo-mcp-server/issues/101)): sent only when set, so `global_tilted_irradiance` no longer returns horizontal irradiance under the tilted name. A `notice` names the plane Open-Meteo fills in when a tilted variable is requested without them.
- **HTTP 408 is retried like a 5xx, and a JSON `null` or scalar response body is an unreadable response**, where 0.6.0 failed a 408 as an input error and a `null` body as an internal error.
- **A `timezone` holding a comma fails as `invalid_timezone`**, with the list-of-zones explanation.
- **`current_variables` on `openmeteo_get_forecast` naming a daily-only variable fails as `variable_wrong_cadence` before any request.**
- **The cadence catalogs accept seven names Open-Meteo serves at both cadences**, which 0.6.0 rejected as `variable_wrong_cadence`: forecast hourly `temperature_2m_max`, `temperature_2m_min`, `growing_degree_days_base_0_limit_50`; archive hourly `temperature_2m_max`, `temperature_2m_min`; ensemble daily `sunshine_duration`, `weather_code`.
- **`openmeteo_get_ensemble` sends its model list with literal commas**, so a rejection of a pair names the one unknown model.
- **The `invalid_variable` recovery on the tools that take `models` no longer calls the rest of the list valid**: Open-Meteo names only the first unknown model, and the retry names the next.
- **`openmeteo_get_ensemble` words `variable_wrong_cadence` by what the API serves**, and its `request_too_large` recovery offers fewer models on a several-model call.
- **`openmeteo_get_ensemble` notice for a name the endpoint parses but does not serve** reads it from a requested model that serves it, or else sends the caller to the tool for that kind of variable, instead of leading with another model.
- **The notice for a column whose unit is `undefined` no longer blames the cadence.**
- **A coverage-gap recovery offers "omit models" only when the tool's default model was not among those requested.**
- **`openmeteo_get_climate` coverage-gap notice no longer ends "Try another model."** when the call named all seven climate models.
- **`openmeteo_dataframe_query` `limit` past the safe-integer range** is lowered to 10,000 with the `notice`; with `OPENMETEO_CLAMP_LIMITS=false` it is rejected naming the cap alone.
- **`openmeteo_search_locations` rejects a negative `count` past the safe-integer range on the minimum alone**; 0.6.0 reported two issues.
