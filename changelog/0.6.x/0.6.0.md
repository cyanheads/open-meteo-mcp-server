# 0.6.0 — 2026-11-10

## Added

- **`openmeteo_dataframe_query` takes `limit`** ([#94](https://github.com/cyanheads/open-meteo-mcp-server/issues/94)): the page size, default 25 rows, at most 10,000 (`CANVAS_DEFAULT_ROW_LIMIT` when lower). A larger value is lowered to the cap with a `notice`; `OPENMETEO_CLAMP_LIMITS=false` advertises the cap as the maximum and rejects a larger value. Output gains `truncated` and `notice`.
- **`cell_selection`** (`land`, `sea`, `nearest`) on `openmeteo_get_forecast`, `openmeteo_get_historical`, `openmeteo_get_ensemble`, and `openmeteo_get_climate` ([#93](https://github.com/cyanheads/open-meteo-mcp-server/issues/93)), sent to Open-Meteo only when set. On climate the response `latitude` / `longitude` can stay the same while the values change.
- **Open-Meteo's own keys and list format on the seven weather tools** ([#96](https://github.com/cyanheads/open-meteo-mcp-server/issues/96)): `hourly`, `daily`, and `current` alias the matching `*_variables` field where the tool has one, and every variable and model list also takes one comma-joined string. `tools/list` is unchanged.

## Changed

- **Breaking: `openmeteo_dataframe_query` refuses a statement that uses the name of a DuckDB internal metadata view as a column alias, CTE name, subquery column, or table alias**, as `system_catalog_access` (for example `duckdb_tables`, `pg_class`, `pragma_database_list`); 0.5.0 answered them. Rename the alias.
- **`openmeteo_dataframe_query` without `limit` returns at most 25 rows** (was 100), including when the SQL's own `LIMIT` asks for more; `truncated: true` and the `OFFSET` notice say more exist. Below a `CANVAS_DEFAULT_ROW_LIMIT` of 25, that cap is the default page and a call without `limit` gets no clamp notice ([#94](https://github.com/cyanheads/open-meteo-mcp-server/issues/94)).
- **`openmeteo_dataframe_query` response bounds** ([#94](https://github.com/cyanheads/open-meteo-mcp-server/issues/94)): the 80,000-character page cut and `row_too_large` are gone. One response carries at most 8,000,000 characters of row data, and a larger page fails as `result_too_large`, never cut. A message relayed from the query engine is cut to 2,000 characters.
- **`openmeteo_dataframe_query` answers `SHOW <table>` and `range()` / `generate_series()` with constant arguments**; 0.5.0 refused them as `plan_operator_not_allowed`.
- **Four `openmeteo_dataframe_query` refusals changed reason and stay refusals:** `SELECT * FROM duckdb_tables` or `pg_tables` (`plan_operator_not_allowed` → `system_catalog_access`), a quoted `"pragma_version"()` call (`plan_operator_not_allowed` → `denied_function`), `COPY … TO` (`sql_read_only` → `non_select_statement`), `DESCRIBE` of a missing table (`non_select_statement` → `missing_table`).
- **A spilled weather response's inline preview holds up to 8,000 characters of rows** ([#95](https://github.com/cyanheads/open-meteo-mcp-server/issues/95)), since the canvas holds the rest; a first row wider than its share still returns whole. The 80,000-character spill threshold and the preview with `CANVAS_PROVIDER_TYPE=none` are unchanged.
- **`openmeteo_get_flood` states that discharge begins 1997-01-01** ([#92](https://github.com/cyanheads/open-meteo-mcp-server/issues/92)) in its descriptions, the `consolidated_v4` note, the server instructions, and the README. Ranges are still accepted from 1984-01-01; earlier days return null with the coverage notice.
- **Under Node, server variables kept only in `./.env` now take effect:** the `OPENMETEO_*` switches and the `OPEN_METEO_*_BASE_URL` overrides, which 0.5.0 ignored under Node (Bun and the framework's own variables were unaffected). An invalid value there now stops startup.
- **Notices on the seven weather tools and `openmeteo_search_locations` render literally in `content[]`:** text Markdown would read as formatting is escaped. `structuredContent.notice` is unchanged.
- **`open-meteo-guide` skill 1.0 → 1.0.1:** `cell_selection` for water points, the flood climatology span, per-model variable gaps (Gate 4), and the query page size.

## Fixed

- **`openmeteo_dataframe_query` table cells and headers in `content[]` read back, under a GFM parse, as the value `structuredContent` carries** ([#86](https://github.com/cyanheads/open-meteo-mcp-server/issues/86)); `structuredContent.rows` is unchanged.
- **Date rejections are recognized by Open-Meteo's own wording** ([#89](https://github.com/cyanheads/open-meteo-mcp-server/issues/89)): an unknown variable or model name containing "date" or "range" on `openmeteo_get_historical`, `openmeteo_get_climate`, or `openmeteo_get_flood` now fails as `invalid_variable`. `openmeteo_get_marine` and `openmeteo_get_air_quality` report an out-of-range date as `date_out_of_range` (was `invalid_variable`).
- **Coverage notices attribute an empty column to its model** ([#90](https://github.com/cyanheads/open-meteo-mcp-server/issues/90)): on forecast, historical, and climate, a variable null under a real unit names the selected model that returned it empty and the model that served it, not the location or window; with one model selected, or every selected model empty, the notice names the model beside the location and window.
- **`openmeteo_get_historical` with `best_match` beside another model** no longer reports `best_match` as having returned no columns ([#90](https://github.com/cyanheads/open-meteo-mcp-server/issues/90)).
- **Gaps at a window's start or end earn a notice under six null rows** ([#91](https://github.com/cyanheads/open-meteo-mcp-server/issues/91)) when those rows are at least 1% of the window, such as the last day of a 35-day ensemble; interior gaps keep the six-row floor.
- **`openmeteo_search_locations` rejects a `country` that is not two letters** with the ISO 3166-1 alpha-2 rule and how to proceed, not the bare pattern ([#97](https://github.com/cyanheads/open-meteo-mcp-server/issues/97)).
- **Output descriptions:** `elevation` on forecast, historical, ensemble, and climate is the requested coordinate's terrain elevation; `latitude` / `longitude` on historical name the cell that answered, and on climate do not.
