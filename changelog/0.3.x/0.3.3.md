# 0.3.3 — 2026-07-30

## Added

- **Documented model catalog for `openmeteo_get_ensemble` and `openmeteo_get_climate`**, via new `src/mcp-server/tools/model-catalog.ts`. Not an allowlist — a model name the catalog doesn't carry still goes upstream untouched, so a model Open-Meteo adds later keeps working; the catalog backs the advertised lists (so description, `models` field description, and `invalid_variable` recovery can't drift apart) and, on `openmeteo_get_climate`, isolates a rejected multi-model request down to the requested names the documentation doesn't publish rather than echoing the whole list. `extractInvalidValues()` is now exported from `upstream-error.ts` so both tools share the same regex. ([#31](https://github.com/cyanheads/open-meteo-mcp-server/issues/31))

## Changed

- **`openmeteo_get_ensemble`'s advertised model list refreshed** — nineteen documented models (`ecmwf_ifs025_ensemble`, `google_weathernext2_ensemble`, `ukmo_global_ensemble_20km`, and sixteen more) replace the four stale, unsuffixed names (`ecmwf_ifs025`, `gfs025`, `icon_seamless`, `gem_global`) the description carried; those older spellings still resolve upstream. The member ceiling is corrected to 64 (`google_weathernext2_ensemble`), not 51, and `member_count` in a response is documented as one lower than the catalog's figure — it counts only the perturbed `_memberNN` columns, not the control run. ([#31](https://github.com/cyanheads/open-meteo-mcp-server/issues/31))

## Fixed

- **`openmeteo_get_forecast`, `openmeteo_get_historical`, and `openmeteo_get_marine` could return an empty `daily` array on a wide hourly window even though daily rows existed upstream.** The canvas-less preview bounded one `boundedPreview()` call over the concatenated `[...hourly, ...daily]` array and split it afterward; hourly records lead, so a wide window spent the whole `PREVIEW_CHARS` budget before the first daily row. New `boundedPreviewByCadence()` bounds each cadence against its own share of the budget instead, guaranteeing each half and releasing the unused portion to the other — measured against a 92-day marine pull (2,400 hourly, 100 daily rows), `daily` goes from empty to all 100 rows inside the same budget. `openmeteo_get_ensemble` already bounded per cadence and needed no change. ([#32](https://github.com/cyanheads/open-meteo-mcp-server/issues/32))
- **A rejected multi-model `openmeteo_get_climate` request named every requested model, valid ones included**, since the `models` array is sent as one percent-encoded comma value and upstream echoes it back whole on rejection. The model catalog above narrows the echo to only the requested names outside the documented set. ([#31](https://github.com/cyanheads/open-meteo-mcp-server/issues/31))
