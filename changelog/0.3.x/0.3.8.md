# 0.3.8 — 2026-09-09

## Changed

- **`describeCoverageGaps()` drops a `partial` gap under 6 null rows** (#52). A single stray null read with the same prominence as a real coverage boundary; `all-null` gaps are unaffected regardless of row count.
- **Truncated responses omit the cadence key that was never requested, instead of emitting `[]`** (#53). `boundedPreviewByCadence()` now returns `undefined` for a cadence it wasn't given, matching the non-truncated path's output-schema contract. Affects `openmeteo_get_forecast`, `openmeteo_get_historical`, `openmeteo_get_marine`, and `openmeteo_get_ensemble` — a caller reading `daily: []`/`hourly: []` on a single-cadence request now sees the key absent instead. `openmeteo_get_marine`'s `daily` output description now states the omission contract.

## Fixed

- **HTTP 429 is no longer retried** (#49). Classified by status ahead of every body-shape check as a non-retryable `RateLimited`, with the message built from the upstream `reason` when the body carries one (e.g. "Daily API request limit exceeded. Please try again tomorrow.") and window-agnostic fallback wording otherwise, naming Open-Meteo's separate per-minute/per-hour/per-day limits instead of asserting a fixed reset.
- **`request_too_large` declared on all seven time-series tools** for Open-Meteo's "Your API call requests too much data…" rejection (#50), previously misclassified as `invalid_variable` and pointed the caller at a spelling check on names that were already correct.
- **Canvas-disabled truncation disclosure now reaches `structuredContent`, not just `content[]`** (#51). The seven spill-capable tools compose `noCanvasNotice()` into `notice` on the no-canvas branch, matching how the canvas-pointer branch already discloses on both surfaces.
- **`docs/design.md`'s resilience section** corrected to describe the current retry set (`ServiceUnavailable`, `Timeout` — not rate limits).
