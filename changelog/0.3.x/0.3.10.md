# 0.3.10 — 2026-09-16

## Added

- **`createApp({ sessionMode: 'stateless' })` declares the HTTP session posture in `src/index.ts`** (#47). An HTTP run with `MCP_SESSION_MODE` unset now resolves stateless, where the schema default `auto` resolved stateful; `.env.example` and the Docker image already pinned `stateless`, and the env var still overrides. The server card also publishes the resolved mode under `_meta` key `io.github.cyanheads.mcp-ts-core/sessionMode` ([mcp-ts-core#387](https://github.com/cyanheads/mcp-ts-core/issues/387)).

## Changed

- **`@cyanheads/mcp-ts-core` ^0.12.8 → ^0.13.2.** Client-visible: an empty or unsubstituted `${…}` env value now reads as unset ([mcp-ts-core#427](https://github.com/cyanheads/mcp-ts-core/issues/427)); a cancelled HTTP request's SSE stream closes immediately instead of waiting for keep-alive ([mcp-ts-core#401](https://github.com/cyanheads/mcp-ts-core/issues/401)); SIGTERM/SIGINT now exit the process explicitly ([mcp-ts-core#435](https://github.com/cyanheads/mcp-ts-core/issues/435)). The contract test for undeclared arguments now asserts `InvalidParams` (`-32602`), the code clients already received ([mcp-ts-core#416](https://github.com/cyanheads/mcp-ts-core/issues/416)).
- **Framework skill tree moved from `skills/` to `framework-skills/`** ([mcp-ts-core#428](https://github.com/cyanheads/mcp-ts-core/issues/428)) — Claude Code and Codex auto-load a plugin's root `skills/`, so shipping `.claude-plugin/`/`.codex-plugin/` handed development skills to every installing agent.
- Engines floor: Bun `>=1.3.0` → `>=1.4.0`.
- Plugin manifests gain `$schema` (Claude), author contact, and keywords; `server.json`'s description trims a redundant "archive" qualifier.

## Fixed

- **`manifest.json` wires `CANVAS_PROVIDER_TYPE` into `user_config`/`mcp_config.env`**, satisfying the framework's new MCPB wiring check (`lint:packaging` check 11) — the option was declared but never referenced, so a host collected the value and dropped it.

## Security

- **`stripSqlComments`, run over the SQL `openmeteo_dataframe_query` sends to a staged canvas, is now a linear-time scan** rather than a polynomial-time regex ([mcp-ts-core#431](https://github.com/cyanheads/mcp-ts-core/issues/431), CodeQL `js/polynomial-redos`).
