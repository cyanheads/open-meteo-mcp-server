# 0.3.6 — 2026-09-09

## Changed

- **`MCP_SESSION_MODE` documented default is `stateless`** (#47). `.env.example` now sets it uncommented; the README table documents `auto | stateful | stateless`, noting `auto` resolves to `stateful`. Declaring the mode in `src/` stays blocked on `cyanheads/mcp-ts-core#376` — no `sessionMode` option exists on `createApp` at 0.12.8.

## Fixed

- **Coverage-gap recovery names the dataset's own grid on tools without a `models` field** (#45). `openmeteo_get_forecast`, `openmeteo_get_historical`, `openmeteo_get_marine`, `openmeteo_get_air_quality`, and `openmeteo_get_flood` no longer tell callers to switch models — a parameter they don't expose; only `openmeteo_get_ensemble` and `openmeteo_get_climate` keep that recovery. Both branches now name the refused coordinate.
- **Declared `invalid_timezone` reason across all seven time-series tools** (#38). A blank `timezone` is rejected before the call instead of silently resolving to GMT; an upstream-unrecognized zone reclassifies from `invalid_variable` to `invalid_timezone`.
- **`date_order_invalid` on `openmeteo_get_marine` and `openmeteo_get_air_quality`** (#39). A reversed `start_date`/`end_date` pair — previously misclassified as an unknown variable — now throws before the call, naming the actual problem.
- **`openmeteo_search_locations` `no_results` recovery covers 1–2 character native-script names** (#46). A short native-script query ("서울", "大阪") matches only an index entry of that exact length; the recovery text and the `name`/`language` field descriptions now say to retry with the full administrative name or the romanized form.
