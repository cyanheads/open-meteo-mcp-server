# 0.3.4 — 2026-07-30

## Changed

- **Comma-joined list parameters (`models`, `hourly`, `daily`, and the elevation coordinate lists) now go on the wire with a literal comma** instead of through `URLSearchParams`, which percent-encodes the comma and makes upstream read the whole list as one value. New `openMeteoUrl()` in `open-meteo-service.ts` replaces the four ad hoc `URL`/`URLSearchParams` builders; every value is `encodeURIComponent`-escaped per element, and an empty value is omitted rather than sent as a bare `key=`. Upstream now isolates the single offending entry in a rejection (`invalid String value BOGUS_MODEL` instead of the whole requested list), so `frameInvalidVariableMessage()` never has to guess which of several named values is actually invalid. The climate-specific `isolateUnknownClimateModels()`/`describeUnknownClimateModels()` workaround in `model-catalog.ts` is removed — it reconstructed the offender from a local catalog that had to be refreshed to stay correct, which is exactly what deferring to upstream avoids. ([#34](https://github.com/cyanheads/open-meteo-mcp-server/issues/34))

## Fixed

- **`openmeteo_get_forecast`, `openmeteo_get_historical`, and `openmeteo_get_marine`'s canvas branch could return an empty `daily` preview even though daily rows existed upstream**, because it split `spillover()`'s `previewRows` back apart by timestamp shape — those rows are drained from the head of the concatenated array, so a wide hourly window left none of them daily. All three now call `boundedPreviewByCadence()` on the canvas branch too, matching the canvas-less branch; `splitByCadence()` had no remaining callers and is removed. ([#36](https://github.com/cyanheads/open-meteo-mcp-server/issues/36))
- **`openmeteo_get_ensemble` measured each cadence against the full `PREVIEW_CHARS` budget separately**, so its two-cadence preview carried roughly twice the inline ceiling every other two-cadence tool caps at — on the widest payload the server serves. Both branches now call `boundedPreviewByCadence()` to share one budget. Measured on a 64-member, 108-day pull (193 columns, ~6 KB/row): 157,527 combined characters before, 78,999 after, with 7 hourly and 6 daily rows surviving rather than either cadence starving. ([#35](https://github.com/cyanheads/open-meteo-mcp-server/issues/35))
- **A regional ensemble model queried outside its coverage area surfaced as a transient API outage after 3 retries.** Most regional models answer with HTTP 200 and a body carrying `nan` coordinates and no data blocks (`icon_eu_eps`, `icon_d2_eps`, `ecmwf_ifs_europe_ensemble`, `ecmwf_aifs_europe_ensemble`, `ukmo_uk_ensemble_2km`); the `meteoswiss_*` pair instead returns a 400 with `No data is available for this location`. The `nan` body isn't valid JSON, so it reached `JSON.parse`, threw, and was classified as a retryable transient failure. The service now matches both shapes before the retry loop runs and throws a single non-retryable `ValidationError` naming the coverage gap and the fix — a request against either shape now fails on the first attempt instead of burning three. ([#33](https://github.com/cyanheads/open-meteo-mcp-server/issues/33))
