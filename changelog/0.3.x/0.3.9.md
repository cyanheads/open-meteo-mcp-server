# 0.3.9 — 2026-09-09

## Added

- **`current_variables` on `openmeteo_get_forecast` and `openmeteo_get_air_quality`** (#42). Returns conditions at this instant as a `current` object plus `current_units`, and satisfies the variable requirement on its own — no hourly series needed. `interval` reports the update cadence in seconds (900 on forecast, 3600 on air quality) and is counted against the inline response budget alongside the other unit maps.
- **`models` on `openmeteo_get_historical`** (#37). Array input, sent upstream as a literal comma-joined list and echoed back on `structuredContent` and `content[]`. `cerra` requested outside Europe now reaches the same model-switch coverage-gap recovery as the ensemble and climate tools.
- **`openmeteo_search_locations` enrichment `notice`** (#48). Fires when the top match's population is null or under 100,000 — the shape a historic or colonial exonym returns (e.g. "Bangalore", "Calcutta", "Peking" resolving to unrelated small features rather than the modern city). Advisory only; never changes `results` or `count`.

## Changed

- **Omitted `models` on `openmeteo_get_historical` relabeled from ERA5 to Open-Meteo Best Match** across the tool description, README, server instructions, and config docs — the default blends IFS HRES, ERA5, and ERA5-Land rather than serving pure ERA5.
- **`openmeteo_get_flood` description and coordinate fields corrected to "largest modeled river within 5 km"** (#43), replacing the inaccurate "snaps to nearest river" claim, with Open-Meteo's ±0.1° coordinate-variation guidance for an unrepresentative result.
