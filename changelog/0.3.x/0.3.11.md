# 0.3.11 — 2026-09-21

## Added

- **`.github/workflows/codeql.yml`** — the one GitHub Actions workflow this project carries; runs only while the repo's CodeQL default setup is off.

## Changed

- **`canvas_id` inputs on the nine canvas-aware tools validate against the minted token shape** `^[A-Za-z0-9_-]{10}$` at argument validation, via mcp-ts-core 0.13.5's `CanvasIdSchema` ([cyanheads/mcp-ts-core#327](https://github.com/cyanheads/mcp-ts-core/issues/327)) — a malformed id is rejected as `invalid_arguments` before any upstream request or canvas lookup. Required on `openmeteo_dataframe_describe`/`openmeteo_dataframe_query`, optional elsewhere; output `canvas_id` fields stay plain strings.
- **Tool error text ends with `(reason <reason>)`**, plus `· not retryable` / `· retryable` when the error states it (mcp-ts-core 0.13.5, [cyanheads/mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)); `structuredContent` is unchanged.
- **Argument rejections carry `data.reason: "invalid_arguments"` and a synthesized recovery hint** (mcp-ts-core 0.13.3, [cyanheads/mcp-ts-core#445](https://github.com/cyanheads/mcp-ts-core/issues/445)); an unknown key's hint names the keys the tool accepts. The `Recovery:` line is left out of the text when it would repeat the message, as it does for a malformed `canvas_id`; `data.recovery.hint` stays populated (mcp-ts-core 0.13.5, [cyanheads/mcp-ts-core#459](https://github.com/cyanheads/mcp-ts-core/issues/459)).
- **Tool arguments are normalized before validation** (mcp-ts-core 0.13.4): a key sent in another case style (e.g. `hourlyVariables`) maps to the declared key ([cyanheads/mcp-ts-core#452](https://github.com/cyanheads/mcp-ts-core/issues/452)); the client-added root keys `_meta`, `tool_call_description`, and `toolCallId`, and any other undeclared key starting with `_`, are dropped ([cyanheads/mcp-ts-core#453](https://github.com/cyanheads/mcp-ts-core/issues/453)); and an array sent as a JSON-encoded string is decoded and re-validated once ([cyanheads/mcp-ts-core#234](https://github.com/cyanheads/mcp-ts-core/issues/234)). Any other undeclared key is still rejected; `inputSchema` is unchanged.
- **`openmeteo_dataframe_query` reports a DuckDB data error — a `Conversion`, `Invalid Input`, or `Out of Range` error raised on the staged rows — as a `ValidationError` (`-32007`)** with `data.reason: "sql_execution_error"` and a recovery hint, where it was a `DatabaseError` (`-32010`) with neither (mcp-ts-core 0.13.4, [cyanheads/mcp-ts-core#451](https://github.com/cyanheads/mcp-ts-core/issues/451)). The SQL-gate rejections it passes through (`non_select_statement`, `multi_statement`, …) and a DuckDB parse error now carry a recovery hint too ([cyanheads/mcp-ts-core#299](https://github.com/cyanheads/mcp-ts-core/issues/299)).
- **Each tool's advertised `error.data.reason` description in `outputSchema` ends every declared `when` clause with a period**, so the entries no longer run together (mcp-ts-core 0.13.5, [cyanheads/mcp-ts-core#389](https://github.com/cyanheads/mcp-ts-core/issues/389)) — description text only.
- Framework skills, `changelog/template.md`, `scripts/lint-mcp.ts` (reads `lint.truncationAllowlist` from `devcheck.config.json`), and the GH issue forms synced to mcp-ts-core 0.13.6; `CLAUDE.md`/`AGENTS.md` gain a Publishing section and the one-workflow CI note.
