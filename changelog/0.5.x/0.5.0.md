# 0.5.0 — 2026-10-28

## Added

- **`open-meteo-guide` agent skill** — served at `skill://open-meteo-guide/SKILL.md` (with the `skill://{+path}` template, so `references/weather-codes.md` resolves too) through `createApp({ skills })`, and shipped under `skills/` in the npm package, Docker image, and `.mcpb`. The server `instructions` point to it.

## Changed

- **Enrichment-trailer string values in `content[]` render as code spans** (mcp-ts-core 0.13.18), e.g. `**Effective language:** \`ru\``; error and trailer text in `content[]` gains Markdown escapes (0.13.16); `openmeteo_search_locations` place names in `content[]` are Markdown-escaped. `structuredContent` is unchanged.
- **`openmeteo_get_flood`, `openmeteo_get_marine`, `openmeteo_get_historical`, `openmeteo_get_forecast` descriptions and `recovery` text** reworded per the corrections below; no behavior change.

## Fixed

- **`openmeteo_get_flood`** reads discharge from the GloFAS 0.05° grid cell nearest the coordinate, not "the largest modeled river within 5 km"; the guidance is now to step 0.05° across the channel (was ~0.1°) when the value is far below the named river's flow.
- **`openmeteo_get_marine`** describes a coastal land point as answered from a nearby sea cell with real values and no notice; only a point well inland returns nulls.
- **ERA5-family archive models** (`era5`, `era5_land`, `era5_ensemble`) are described as about a week behind (was ~1–5 / 5 days) ([#87](https://github.com/cyanheads/open-meteo-mcp-server/issues/87)).
- **The `.mcpb` no longer ships** `tests/`, `coverage/`, `src/`, `scripts/`, `.github/`, `.vscode/`, `docs/`, `changelog/`, agent instruction files, or the framework's build-only files (template `.mcpbignore`, 0.13.18) ([#84](https://github.com/cyanheads/open-meteo-mcp-server/issues/84)).
