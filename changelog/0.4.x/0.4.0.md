# 0.4.0 — 2026-10-03

## Added

- **`openmeteo_dataframe_drop`** — removes one table or view from a DataCanvas and returns `dropped` plus the `remaining_tables`. Idempotent: dropping a name that isn't staged returns `dropped: false`; an input that can never name a table fails as `invalid_table_name`.
- **`OPENMETEO_DATAFRAME_DROP_ENABLED`** (default `false`) — `true` makes `openmeteo_dataframe_drop` callable and names it in the server instructions. Unset, the tool is still listed in the manifest as disabled, with the enable hint. It has no effect unless `CANVAS_PROVIDER_TYPE=duckdb` is also set. Declared in `server.json`, `manifest.json`, and `.env.example`.

## Changed

- **Tool error `data` carries `requestId`, and the error text ends with `request <id>`** (mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)).
- **Declared recovery hints are filled from each tool's `errors[]` contract** (mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)) — this server dropped its per-site `ctx.recoveryFor` forwards; the hint text callers receive is unchanged.
- **A result that breaks a tool's declared output contract fails as `-32603` instead of `-32007`** (mcp-ts-core 0.13.8, [cyanheads/mcp-ts-core#480](https://github.com/cyanheads/mcp-ts-core/issues/480)).
- **A JSON-stringified object, or an integer sent for a string field, is repaired before validation** (mcp-ts-core 0.13.9, [cyanheads/mcp-ts-core#479](https://github.com/cyanheads/mcp-ts-core/issues/479), [#487](https://github.com/cyanheads/mcp-ts-core/issues/487)). Argument rejections name field paths and any alias rewrite ([cyanheads/mcp-ts-core#468](https://github.com/cyanheads/mcp-ts-core/issues/468), [#493](https://github.com/cyanheads/mcp-ts-core/issues/493)).
- **DuckDB canvas scratch files live in a private per-process directory, and `CANVAS_TEMP_PATH` now names its parent** (mcp-ts-core 0.13.9, [cyanheads/mcp-ts-core#554](https://github.com/cyanheads/mcp-ts-core/issues/554)).
- **MCP SDK `@modelcontextprotocol/server` ^2.0.0 → ^2.1.0 (mcp-ts-core 0.13.9) → ^2.2.0 (mcp-ts-core 0.13.11)** — a 2026-07-28 POST without `MCP-Protocol-Version` is refused `400`.
- **Docker image** — production dependencies install in a `deps` stage on the build platform, so no Bun runs under emulation, and musl-only native packages are dropped (adopting mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575), and 0.13.11, [cyanheads/mcp-ts-core#608](https://github.com/cyanheads/mcp-ts-core/issues/608)). OTel packages install through `scripts/install-otel.ts`; base images move to `oven/bun:1.4.2`.
- **`errors[].when` texts** are complete sentences, and the date-order, window-conflict, cadence, and coordinate-count conditions are restated; each tool's advertised `error.data.reason` description shows them (description text only).
- **README** — the overview, tool table, and capability reference are condensed, `openmeteo_dataframe_drop` is documented, and the configuration table leads with this server's own variables.
- **`.env.example`** adds the commented framework variables `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS` / `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, and the per-signal `OTEL_EXPORTER_OTLP_*_ENDPOINT` overrides.
- **Ignore rules** — `.gitignore` ignores `.env*` except `.env.example`, `.env.template`, and `.env.sample`; `.dockerignore` excludes `.env*` and the MCP registry token files; `.mcpbignore` excludes `docs/idea.md` and `logs/`.
- **CodeQL workflow** runs one job per language, uploading under `/language:<language>`; a required `Analyze` check becomes `Analyze (actions)` and `Analyze (javascript-typescript)`.
- Framework skills and scripts synced to mcp-ts-core 0.13.11 (`lint:mcp` load-failure errors, `lint:packaging` checks 13–16, `release:github` tag validation); `package.json` `files` excludes `dist/*.mcpb`; `CLAUDE.md`/`AGENTS.md` describe the recovery fill and the drop tool.
- Tests: `tests/tools/dataframe-drop.tool.test.ts` and `tests/config/server-config.test.ts` (base URLs and the drop flag) are new; error-path tests assert through `runToolContract` via `tests/helpers/wire-error.ts`.

## Fixed

- **`server.json` npm entries drop the `run start:*` package arguments and set `runtimeHint: npx`, and the `streamable-http` entry fixes `MCP_TRANSPORT_TYPE` to `http`** (adopting mcp-ts-core 0.13.11, [cyanheads/mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622)) — a registry client launching the HTTP entry now gets the HTTP transport.
- **Concurrent canvas spills no longer corrupt each other** (mcp-ts-core 0.13.9, [cyanheads/mcp-ts-core#561](https://github.com/cyanheads/mcp-ts-core/issues/561)).
- **A canvas `missing_table` error means a missing table; an unknown function or type is `invalid_sql`** (mcp-ts-core 0.13.8, [cyanheads/mcp-ts-core#484](https://github.com/cyanheads/mcp-ts-core/issues/484)).
- **`ctx.log` notifications to the client honor `MCP_LOG_LEVEL` and mask sensitive fields** (mcp-ts-core 0.13.11, [cyanheads/mcp-ts-core#621](https://github.com/cyanheads/mcp-ts-core/issues/621), [#630](https://github.com/cyanheads/mcp-ts-core/issues/630)).
